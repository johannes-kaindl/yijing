# Design: Yijing Data Correctness & Rendering (Sub-project A)

- **Date:** 2026-05-31
- **Status:** Approved for spec review
- **Scope:** Sub-project A of two. Sub-project B (export repair: native macOS
  bridge + two PDF modes + Markdown save) is specified separately and is **out
  of scope here**.

## 1. Context & problem

The app's hexagram texts (`data/hexagrams.json`, mirrored in
`data/hexagrams.en.json`) are generated by `scripts/build_data.py` from the
read-only `_archiv/` sources (primarily `_archiv/Yijing_6/.../hexagram_json/`).
A data audit found concrete gaps and defects that matter because users treat
the output as divination:

- **Empty `meaning`** for hexagrams **17, 25, 47, 48, 53, 56** (the source
  JSONs carry `"meaning":{"description":""}`).
- **Empty `image`** for hexagram **2** (The Receptive).
- **OCR typo** in hexagram **5** `image`: `Dorotbea` → `Dorothea` (Goethe,
  "Hermann und Dorothea").
- **Missing 7th line** for hexagrams **1 and 2** — the traditional
  *"use the nine" / "use the six"* all-lines-moving oracle. For these two pure
  hexagrams the single most significant cast (all six lines moving) currently
  has no text.
- **17 of 19 `image_association`** values are truncated mid-word and carry a
  leaked filename-numbering suffix (`-2`, `-10`, `-15`). Root cause: the
  filename-stripping regex in `load_image_prompts()` is too narrow, and
  `max(..., key=len)` deliberately prefers the longer (suffixed) variant.
- **Inconsistent quotation marks**: guillemets `»…«` dominate but straight
  ASCII `"` appears in 10 fields; German typographic `„…"` never. Some fields
  mix both for the same quotation.

Projekt-Gutenberg hosts the public-domain Richard Wilhelm 1924 translation and
is **complete** (all 64 hexagrams, one page each, with meaning + Judgment +
Image + the 6 lines and their commentary, including the 7th oracle for hex
1 & 2). It is the canonical ground-truth source we will re-source from.

Recon notes on the Gutenberg source (verified):
- WordPress-backed, **UTF-8**. URL pattern:
  `https://projekt-gutenberg.org/authors/richard-wilhelm/books/i-ging/chapter/{N}`
  for `N = 3..66` (chapter 1 = title page, chapter 2 = a modern coin-toss
  intro — **not** Wilhelm).
- **Chapter number ≠ hexagram number.** The page order is scrambled; the
  scraper MUST parse the hexagram number from the page `<h2>`, never infer it
  from the URL.
- Each page's content is **duplicated** (visible copy + hidden reading-mode
  copy) — dedupe to the first `book-reader__chapter-content-wrapper`.
- `class="em"` is overloaded: it marks both the italic oracle text and inline
  footnotes/parentheticals. Distinguish by content/position.
- Line markers: the German intro phrases (`… bedeutet:`) are the reliable
  delimiters; the `<a name="…_linie">` anchors are inconsistent.
- The source has its own OCR artifacts to guard against (e.g. "das
  Schöpferisch", "Kungtse::", "DIE WIEDERKEHRT", "DAS HAFTENE").

## 2. Decisions (from brainstorming)

- **Gutenberg is canonical; "Gutenberg wins" on divergence** — for the Wilhelm
  *text* fields (`meaning`, `judgment`, `image`, `lines[]`), the Gutenberg text
  is adopted automatically wherever it differs from the current data. No
  blocking review gate. Responsible safeguards: an explicit fix-map for known
  Gutenberg OCR artifacts, plus a non-blocking diff report for transparency.
- **Lookup fields stay as-is** — `name_chinese`, `pinyin`, `name_latin`,
  `trigrams`, `binary`, `unicode` continue to come from `_archiv`/CSV (with the
  existing `FALLBACK_NAMES` for 26 & 42). Gutenberg is not used for these.
- **Quotation marks normalize to `»…«`** (authentic Wilhelm/Gutenberg style),
  applied consistently across the text fields. (Unrelated to the JS-string
  `„…"` rule in AGENTS.md, which is about source literals, not JSON content.)
- **Paragraph rendering** — multi-paragraph texts are stored with `\n\n`
  paragraph separators and rendered as real `<p>` elements (currently a single
  `textContent` string with CSS `white-space: pre-wrap`).
- **EN parity** — re-translate to English only the fields that were newly
  filled or *substantively* changed (Wilhelm-EN style, matching the existing
  translation), to avoid retranslating the whole corpus.
- **Footnotes are preserved, not discarded** — Wilhelm's footnotes carry real
  interpretive content (comparative-religion parallels — Genesis, Zeus, Ikarus,
  Luzifer — calendrical associations, philosophical exposition), some tied to a
  specific line (e.g. the Ikarus/Luzifer note on the top line of hex 1 & 2).
  They are extracted into a structured `notes` field and rendered as a dimmed
  "Anmerkungen" block, separate from the clean main text. EN parity applies.
  Because `class="em"` is overloaded (oracle text / footnotes / inline
  parentheticals all share it), footnote detection is heuristic and **its
  output is validated in the mandatory verification pass** (§7a).
- **Source-asset location** — committed parsed source at
  `scripts/sources/gutenberg_iging.json`; raw HTML cache gitignored. (User may
  prefer `data/sources/`; trivial to relocate.)

## 3. Goals & non-goals

**Goals**
1. Fill every audited gap and fix the known typos so all 64 hexagrams have
   complete, correct Wilhelm text including the 7th line for hex 1 & 2.
2. Re-source the Wilhelm text fields from Gutenberg as canonical, deterministic
   and reproducible (offline re-runs from cache).
3. Preserve paragraph structure so the reading renders cleanly.
4. Repair the `image_association` truncation and the build bug that caused it.
5. Keep DE/EN structurally symmetric (`test-kingwen.mjs` passes).
6. Add a build-time guard so future empty/garbled fields surface instead of
   shipping silently.

**Non-goals**
- No framework, no build step, no new app runtime dependency (AGENTS.md).
- No rewrite of the lookup-field provenance.
- No export/PDF/Markdown work (sub-project B).
- No translation of the scholarly front matter or Buch II appendices (not in
  the app's scope).

## 4. Architecture

Two Python scripts (the data pipeline is already Python; these are build-time
tools, not app dependencies) plus targeted edits to `build_data.py`, `app.js`,
`style.css`, and a separate EN-delta translation step.

```
Gutenberg chapter/3..66
        │  (scrape_gutenberg.py: fetch → cache HTML → parse → normalize → validate)
        ▼
scripts/sources/gutenberg_iging.json        ← committed source asset (64 hexagrams)
        │
        │  build_data.py  (Wilhelm text fields: Gutenberg wins;
        │                  lookup fields: _archiv/CSV as before)
        ▼
data/hexagrams.json (DE)  +  diff report (informational, gitignored)
        │
        │  EN-delta translation (Claude, Wilhelm-EN style; changed/new fields only)
        ▼
data/hexagrams.en.json (EN)
        │
        ▼
node scripts/test-kingwen.mjs  → DE/EN symmetry + King-Wen lookups
web/app.js + web/style.css     → paragraph rendering + hex-1/2 all-moving 7th line
```

### 4.1 `scripts/scrape_gutenberg.py` (new)

Responsibilities:
- Fetch `chapter/3..66` with a realistic browser User-Agent and a polite delay.
  Cache each raw page to `scripts/sources/.html_cache/chapterNN.html`
  (gitignored). Re-runs read from cache unless `--refetch` is passed → offline,
  reproducible, reviewable.
- For each page: isolate the **first** `book-reader__chapter-content-wrapper`
  (dedupe), parse the leading `<h2>` with a tolerant regex
  `^\s*(\d{1,2})\s*\.?\s+(.+?)\s*/\s*(.+)$` → `(hexNumber, romanizedName,
  germanName)`. **Index output by parsed `hexNumber`.**
- Extract, in document order:
  - **meaning** — the intro/`Zeichen` commentary paragraphs before the first
    Judgment oracle.
  - **judgment** — the `em`-italic oracle line(s) after the intro + the
    following `<p>` commentary.
  - **image** — after the `DAS BILD` plain-text heading: `em`-italic oracle +
    `<p>` commentary.
  - **lines** — after `<hr>` + `Die Einzelnen Linien`: split on the
    `… bedeutet:` phrases into the 6 lines (ordinal from the German phrase:
    "Anfangs"=1 … "Oberste"=6), each = `{position, text, interpretation}`.
    For hex **1 & 2**, additionally capture the 7th entry
    ("Wird lauter Neunen/Sechsen gebraucht …") as `lines[6]`.
  - **footnotes** — captured into a structured `notes` array (NOT discarded).
    Detection heuristic: an `em`-span that is wholly parenthetical `(…)` and/or
    carries the `*` anchor, sitting inside a `<p>` commentary paragraph (i.e.
    not the oracle text that directly follows a Judgment/Image/line heading).
    Each note records `{marker, text, anchor}` where `anchor` is the section it
    was attached to (`meaning` / `judgment` / `image` / `line:<n>`), so it can
    be rendered near its context. The bare `*` anchor marker is removed from
    the note text. Detection is acknowledged-fragile and is checked in the
    verification pass (§7a) — the fallback for an unparseable page is per-note
    manual confirmation against the source.
- Normalize: `<br />` → `\n` (single line break within an oracle statement),
  paragraph boundaries → `\n\n`, collapse runs of spaces/tabs, normalize quotes
  to `»…«`, apply the **OCR fix-map** (section 4.6).
- Validate (hard fail with a clear message otherwise): exactly 64 distinct
  hexagram numbers 1..64, no duplicates; each with non-empty `judgment`,
  `image`, and 6 lines; hex 1 & 2 have a 7th line.
- Output `scripts/sources/gutenberg_iging.json`: an object keyed by hexagram
  number (string) — see schema in §4.2.

### 4.2 `scripts/sources/gutenberg_iging.json` schema

```json
{
  "1": {
    "number": 1,
    "name_romanized": "KIEN",
    "name_de": "DAS SCHÖPFERISCHE",
    "meaning": "…\n\n…",
    "judgment": "…\n\n…",
    "image": "…\n\n…",
    "lines": [
      { "position": "Anfangs eine Neun bedeutet:", "text": "…", "interpretation": "…" },
      "… 5 more …",
      { "position": "Wird lauter Neunen gebraucht, so bedeutet das:", "text": "…", "interpretation": "…" }
    ],
    "notes": [
      { "anchor": "meaning", "marker": "*", "text": "Das Zeichen ist dem 4. Monat …" },
      { "anchor": "line:6",  "marker": "*", "text": "Während die oberste Linie … Ikarus … Luzifer …" }
    ]
  }
}
```

`name_romanized`/`name_de` are captured for cross-checking against the existing
`name_de`/`name_latin` but are **not** authoritative (lookup fields win); a
mismatch is reported, not auto-applied. The `notes` array carries Wilhelm's
footnotes with their attachment point (`anchor`) so the app can render them in
context.

### 4.3 `scripts/build_data.py` (modified)

- Add a loader `load_gutenberg()` that reads
  `scripts/sources/gutenberg_iging.json` (hard fail if absent, pointing at
  `scrape_gutenberg.py`).
- In `build()`, the Wilhelm text fields (`meaning`, `judgment`, `image`,
  `lines`, `notes`) come from the Gutenberg entry for that hexagram
  (**Gutenberg wins**). `load_wilhelm_text()` / `_norm_v1` / `_norm_v2` (the
  `_archiv/Yijing_6` readers) are retained only as a fallback if a Gutenberg
  field is unexpectedly empty, and that fallback emits a warning.
- `notes` is copied into `data/hexagrams.json` as a new field (an array of
  `{anchor, marker, text}`; empty array when a hexagram has no footnotes). The
  app data schema (`docs/DATA.md`) gains this field; EN parity adds `text_en`
  per note (see §4.7).
- Lookup fields, trigrams, `binary`, `unicode`, `name_de`/`name_latin` parsing,
  and `FALLBACK_NAMES` are unchanged.
- **Diff report**: before writing, load the previous `data/hexagrams.json` (if
  present) and emit `scripts/sources/gutenberg_diff_report.md` (gitignored)
  listing, per hexagram and field: `filled` (was empty), `changed`
  (text differs — with a short before/after excerpt), `unchanged`. Print a
  one-line summary to stdout. Informational, **non-blocking**.
- **Build guard** (`assert_complete()`): after assembly, fail (non-zero exit)
  if any `meaning`/`judgment`/`image` is empty, any line subfield is empty, or
  any `image_association` still matches a leftover `-\d+$` / truncation
  pattern. Extends the existing stats line.

### 4.4 `image_association` repair

- Fix `load_image_prompts()`:
  - Broaden the suffix-stripping to also remove generic trailing `-\d+`
    filename-numbering (not only the ` p`/`p-N` pattern).
  - Stop preferring the longest candidate when it is the truncated/suffixed
    one; prefer the *un-suffixed* candidate, falling back to length only among
    equally-clean candidates.
- Hand-correct the 17 affected values (hex 2,3,4,5,6,7,11,27,28,56,57,58,59,
  60,61,62,63) to clean keyword strings in a small override map, since the
  underlying source filenames are filesystem-truncated and cannot be fully
  recovered programmatically. These are self-authored atmospheric keywords, not
  Wilhelm text — lower stakes, but they are user-visible so they must be clean.
- Fixing the DE value fixes EN automatically (associations are copied, not
  translated).

### 4.5 Rendering changes (`web/app.js`, `web/style.css`)

- **Paragraph builder** in `app.js`: add a helper that takes a text field,
  splits on `\n{2,}`, `escapeHTML`s each paragraph (reuse the existing
  `escapeHTML` at `app.js:318`), converts single `\n` within a paragraph to
  `<br>`, and joins as `<p>…</p>`. Apply to `judgmentText`, `imageText`,
  `meaningText` (currently `.textContent` at `app.js:348-350`), the
  `resultingJudgment`, and the changing-line `.interp` (in
  `renderChangingLines`, `app.js:283-296`). XSS-safe (escape first; data is
  trusted but escaped regardless).
- `style.css`: replace the `white-space: pre-wrap` reliance on the text-body
  rule (~`style.css:364-369`) with `<p>` paragraph spacing (margins between
  paragraphs); keep line-height/size. Verify the `@media print` block still
  reads well with paragraphs (this also benefits sub-project B).
- **Hex 1 & 2 all-moving 7th line** (logic): in `showReading`
  (`app.js:333+`), when `primaryHex.number ∈ {1, 2}` **and** all six lines are
  changing (`changingIndices.length === 6`), surface `primaryHex.lines[6]`
  (the "use the nine/six" oracle) as the governing changing-line reading
  instead of the six individual line texts. The data layer guarantees
  `lines[6]` exists for 1 & 2 and is absent for all others; rendering keys off
  presence + the all-moving condition.
- **Footnotes / `notes` rendering**: render `notes` as a dimmed, smaller
  "Anmerkungen" block within the `texts` section (new `#notesText`, e.g. a
  collapsed `<details>` like the other text blocks). Each note shows its text
  (language-selected `text_en || text`); where `anchor` resolves to a visible
  section, prefix a small superscript marker. Hidden when the hexagram has no
  notes. New i18n key `reading.notes` (DE "Anmerkungen" / EN "Notes"). New CSS
  `.note` style (smaller, `--ink-soft`).

### 4.6 Gutenberg OCR fix-map

A small explicit dict in `scrape_gutenberg.py` mapping known source artifacts
to corrections, applied during normalization. Seed entries from the audit:
`"das Schöpferisch"` → `"das Schöpferische"`, `"Dorotbea"` → `"Dorothea"`,
`"Kungtse::"` → `"Kungtse:"`, `"DIE WIEDERKEHRT"` → `"DIE WIEDERKEHR"`,
`"DAS HAFTENE"` → `"DAS HAFTENDE"`. Each entry carries a short comment with its
provenance. The map is conservative — only unambiguous artifacts — so we adopt
Gutenberg as the user chose without importing its scanning errors.

### 4.7 EN-delta translation

- After the DE build, diff the new `data/hexagrams.json` against the current
  `data/hexagrams.en.json` source values to determine which fields are newly
  filled or substantively changed (whitespace/quote-only changes are ignored).
- Translate just those DE fields to English in the established Wilhelm-EN
  style, in parallel (Claude subagents, as the original EN was produced),
  including the new hex 1 & 2 seventh line (`text_en`, `position_en`,
  `interpretation_en`) and the footnotes (`notes[].text_en`).
- Merge into `data/hexagrams.en.json`, preserving the existing structure.
- This is an assisted process step, not a committed runtime script.

## 5. Data flow & contracts

- `scrape_gutenberg.py` is the only network step; its output JSON is the
  contract consumed by `build_data.py`. The HTML cache makes builds offline.
- `build_data.py` is the single producer of `data/hexagrams.json` and remains
  reproducible from committed inputs (`_archiv/` + `scripts/sources/`).
- `data/hexagrams.json` and `data/hexagrams.en.json` remain committed primary
  assets (per AGENTS.md). `gutenberg_iging.json` is a new committed source
  asset; the HTML cache and diff report are gitignored.

## 6. Error handling

- Scrape: fetch failures and structural surprises (≠64 hexagrams, missing
  Judgment/Image/lines, missing 7th line for 1 & 2) → hard fail with a precise
  message. Cloudflare rate-limit → polite delay + retry; cache prevents
  refetch.
- Build: missing `gutenberg_iging.json` or `_archiv` source → `SystemExit` with
  guidance. `assert_complete()` fails on empty/garbled fields.
- "Gutenberg wins" is bounded by the OCR fix-map and surfaced (not gated) by
  the diff report.
- Rendering: escape all interpolated text; treat missing fields as `—`.

## 7. Testing / verification

1. `python3 scripts/scrape_gutenberg.py` → 64 parsed, validation asserts pass,
   `gutenberg_iging.json` written.
2. `python3 scripts/build_data.py` → runs clean, `assert_complete()` passes,
   counters consistent (`Schriftzeichen: 64/64`, `Bild-Assoziationen` count),
   diff report written; no empty-field warnings.
3. `node scripts/test-kingwen.mjs` → King-Wen lookups + DE/EN structural
   symmetry pass (including the new hex 1 & 2 seventh line in both files).
4. Browser spot-check (hard reload) on hexagrams **1, 2, 5, 17**: paragraphs
   render with spacing; quotes are consistently `»…«`; hex 5 reads "Dorothea";
   hex 17/25/47/48/53/56 show a non-empty meaning; hex 2 shows an image; casting
   hex 1 (or 2) with all six lines moving shows the "use the nine/six" oracle;
   the "Anmerkungen" block shows the footnotes (e.g. the Ikarus/Luzifer note).
5. `node --check web/app.js`.
6. Update `docs/DATA.md` to document the new Gutenberg provenance, the new
   `notes` field, and the resolved gaps.

### 7a. Mandatory verification pass

Because "Gutenberg wins" and footnote detection is heuristic, a one-time
verification pass is part of this sub-project — made tractable so it is **not**
"read all 64 by hand":

- **Automated gates** (must pass before commit): structural asserts (64
  hexagrams, line counts, hex 1 & 2 have 7 lines), `assert_complete()` (no empty
  text fields, no leftover `-\d+` in `image_association`), an integrity check
  for orphan `*` markers and unbalanced parentheses in any text/note,
  `test-kingwen.mjs` (DE/EN symmetry incl. `notes`).
- **Diff-report review**: the human reviews only the *substantive* field changes
  the report flags (expected to be few).
- **Review artifact** (`scripts/build_review.py` → `scripts/sources/review.html`,
  gitignored): renders all 64 hexagrams — meaning / judgment / image / lines /
  the 7th line / notes — exactly as the app would. One scroll-through confirms
  footnotes were captured as footnotes (not mis-classified body text) and no
  body text went missing. This artifact is the seed for sub-project C (§10).

## 8. Risks & open questions

- **Gutenberg parsing robustness** — the WordPress markup and overloaded
  `class="em"` make extraction fiddly; the per-page validation + manual
  spot-check are the mitigation. If a handful of pages resist clean parsing,
  fall back to a per-hexagram manual entry for just those.
- **Footnote misclassification** — the overloaded `class="em"` means a genuine
  inline parenthetical could be captured as a footnote, or vice versa. Mitigated
  by the §7a review-artifact scroll-through (footnotes appear in their own block,
  so a mis-classified body parenthetical is obvious there, and missing body text
  shows as a gap). Conservative detection (require parenthetical + commentary-`<p>`
  context) keeps false positives low.
- **"Gutenberg wins" churn** — if many fields differ substantively, the EN
  re-translation cost grows. The diff report quantifies this before EN work
  starts; the audit suggests most current text is already clean, so divergences
  should be mostly whitespace/quotes (ignored) with few substantive ones.
- **License** — Wilhelm 1924 is public domain (author d. 1930, 70y p.m.a.,
  PD in Germany since 2001); re-sourcing from Gutenberg does not change the
  app's existing licensing posture. The EN translation remains
  AGPL-3.0-or-later (own words).

## 10. Future / backlog — Sub-project C (read-through reader)

A "click/scroll through the entire Yijing" reading mode (like Gutenberg's
chapter navigation) — browse all 64 hexagrams with their full Wilhelm text and
notes, independent of casting. **Explicitly out of scope here**, captured so the
idea isn't lost. The §7a `review.html` artifact is its natural seed: the same
full-corpus render, promoted from a dev verification tool to an in-app browse
view. Worth its own brainstorming → spec when we get there.
