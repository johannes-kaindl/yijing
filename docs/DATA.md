# Data Model

## Overview

Two JSON files in `data/`:

| File | Content | Size |
|---|---|---|
| `hexagrams.json` | 64 hexagrams with Wilhelm texts, trigrams, image associations | ~580 KB |
| `trigrams.json` | 8 trigrams as reference data (family, nature, season, …) | ~3 KB |

Both are generated by the build script `scripts/build_data.py` and are part of
the commit. The **Wilhelm text fields** (`meaning`, `judgment`, `image`,
`lines`, `notes`) are sourced from **Projekt-Gutenberg** as the canonical
edition (scraped by `scripts/scrape_gutenberg.py` into the committed source
asset `scripts/sources/gutenberg_iging.json`); Gutenberg wins over the older
`_archiv/` extraction. The **lookup fields** (`name_chinese`, `pinyin`,
`name_latin`, `trigrams`, `binary`, `unicode`) still come from `_archiv/`/CSV.
On each build, `build_data.py` writes a non-blocking
`scripts/sources/gutenberg_diff_report.md` and runs `assert_complete()` (no
empty text fields, six regular lines per hexagram, no truncated
`image_association`).

## `data/hexagrams.json`

Array of 64 objects, indexed by King Wen order (`number`
1–64). Structural schema per object:

```json
{
  "number": 1,
  "binary": "111111",
  "unicode": "䷀",
  "name_de": "DAS SCHÖPFERISCHE",
  "name_latin": "Kien",
  "name_chinese": "乾",
  "pinyin": "qián",
  "trigrams": {
    "above": {
      "symbol": "☰",
      "binary": "111",
      "name": "乾",
      "pinyin": "qián",
      "family": "Vater",
      "nature": "Himmel",
      "season": "Sommer",
      "direction": "S",
      "associations": "Ausdehnungsenergie; das wärmende Prinzip…"
    },
    "below": { /* analog */ }
  },
  "meaning": "Das Zeichen besteht aus sechs ungeteilten Strichen…",
  "judgment": "Das Schöpferische wirkt erhabenes Gelingen…",
  "image": "Des Himmels Bewegung ist kraftvoll…",
  "image_association": "Endless clear blue sky, sunrise, powerful rising energy…",
  "lines": [
    {
      "position": "Anfangs eine Neun bedeutet:",
      "text": "Verdeckter Drache. Handle nicht.",
      "interpretation": "Der Drache hat in China eine ganz andere…"
    },
    /* 5 weitere */
  ]
}
```

### Field reference

| Field | Source | Description |
|---|---|---|
| `number` | computed | King Wen number 1–64 |
| `binary` | hardcoded | 6 characters, bottom-to-top, 1 = Yang, 0 = Yin |
| `unicode` | `chr(0x4DC0 + n - 1)` | Hexagram symbol from Unicode block |
| `name_de` | `Yijing_6` | German name (e.g. "DAS SCHÖPFERISCHE") |
| `name_latin` | `yijing_5` with fallback | Latin transliteration (e.g. "Kien") |
| `name_chinese` | `yijing_5` | Chinese character (e.g. 乾) |
| `pinyin` | `yijing_5` | Pīnyīn (e.g. "qián") |
| `trigrams.above` / `.below` | derived from `binary` + `trigrams.json` | see below |
| `meaning` | Gutenberg | Wilhelm: introduction / meaning |
| `judgment` | Gutenberg | Wilhelm: "the Judgment" incl. commentary |
| `image` | Gutenberg | Wilhelm: "the Image" incl. commentary |
| `image_association` | `yijing_3` (file names) | Atmospheric image keywords (2/64; see below) |
| `lines[i]` | Gutenberg | Changing lines — position, line text, commentary. Hexagrams 1 & 2 have a 7th entry, the "use the nine / use the six" all-moving oracle (`bedeutet das:`). |
| `notes[i]` | Gutenberg | Wilhelm footnotes — `{anchor, marker, text}` (+ `text_en`). Rendered in the "Anmerkungen" block. |

## Conventions

### Binary notation

We use **bottom-to-top, 1 = Yang, 0 = Yin**, as a 6-digit string:

- `"111111"` = six Yang lines = hexagram 1 (Kien/Creative)
- `"000000"` = six Yin lines = hexagram 2 (Kun/Receptive)
- `"100010"` = Yang at the bottom, then five lines upward = hexagram 3 (Tschun)

This convention is stored in the code as the `BINARY_TO_KING_WEN` table in
`app.js` and in the build script as `KING_WEN_BINARY` (reversed).
Both are the canonical truth; changes must be synchronized.

### King Wen vs. binary

The King Wen order (1–64) is **not** binary. It follows an
arrangement that is ~3000 years old. The Unicode order `U+4DC0…U+4DFF`
follows the King Wen order — hence: `unicode = chr(0x4DC0 + number - 1)`.

In the archived code (`_archiv/Yijing_6/yijing/core/oracle.py`) there was a
bug: `to_binary_number()+1` was treated as the hexagram number. That is
**wrong** — a lookup table is required.

### Schema variants in the sources

`_archiv/Yijing_6/yijing/resources/hexagram_json/hexagram_16.json` deviates
from the schema of the other 63 hexagrams (no `hexagram` wrapper, different
field names, texts as string arrays instead of a single string). The build script
normalizes both variants in `normalize_v1()` / `normalize_v2()`.

(The `hexagram_16` variant only matters as an `_archiv` fallback now that the
Wilhelm text comes from Gutenberg.)

Other known irregularities:

- Hexagrams 26 and 42 are missing in `_archiv/yijing_5/data/processed/
  hexagram_df.csv`. Their characters and Pīnyīn are added manually in the build
  script as the `FALLBACK_NAMES` constant.
- **`image_association` is now 2/64** (hexagrams 1 and 64). 17 of the original
  19 `_archiv/yijing_3/` values were filename-truncated mid-word and
  irrecoverable; they are dropped (`IMAGE_ASSOC_DROP`) rather than shown broken.
  These are self-authored atmospheric prompts, not Wilhelm text — regenerate as
  desired.
- **Hexagram 2 has no "DAS BILD" section in the Gutenberg edition.** Its image
  (`Die Erdbeschaffenheit ist Hingebung …`) is supplied from the canonical
  Wilhelm 1924 text via the documented `GAP_FILL` map in `build_data.py`.
- Resolved gaps (were empty in the old `_archiv` data): `meaning` for hexagrams
  17, 25, 47, 48, 53, 56; the all-moving 7th line for hexagrams 1 & 2. The old
  `image` fields for hexagrams 1/3/5/6/14/15/46 were contaminated with the
  changing-lines section; the Gutenberg re-sourcing fixes this (lines now live
  only in `lines[]`).

## English variant: `data/hexagrams.en.json`

In parallel to `data/hexagrams.json`, an English variant exists with
exactly the same structure plus additional `*_en` fields on the
translatable texts:

- `name_en` (e.g. "THE CREATIVE" for "DAS SCHÖPFERISCHE")
- `meaning_en`, `judgment_en`, `image_en`, `image_association_en` (only where
  the DE `image_association` is present)
- per line: `position_en`, `text_en`, `interpretation_en` (incl. the 7th line
  for hexagrams 1 & 2)
- per note: `text_en`

Lookup fields (`number`, `binary`, `unicode`, `name_chinese`, `pinyin`,
`name_latin`, `trigrams`) are taken 1:1 from the DE JSON and remain unchanged.

The English variant was **translated from the German
Wilhelm text with Claude Opus 4.7**, in parallel across eight subagents (8 hexagrams
each). The style follows the Wilhelm tradition (dignified, contemplative, slightly
archaizing) with classic I Ching vocabulary from the standard English
literature — comparable to Cary F. Baynes' 1950s translation,
but phrased in its own words. The source is public domain (Wilhelm 1924),
the translation is licensed under [AGPL-3.0-or-later](../LICENSE).

When the DE source was re-sourced from Gutenberg, only the **changed or newly
filled** fields were re-translated (the seventh line of hexagrams 1 & 2, the
footnotes, the filled meanings, the decontaminated images, and the
substantively changed lines); unchanged fields kept their existing translation.
`node scripts/test-kingwen.mjs` verifies DE/EN structural symmetry.

Consistency check: `node scripts/test-kingwen.mjs` verifies that the EN file
is structurally symmetric to the DE source (same `number`/`binary`,
parallel `_en` fields wherever the DE counterpart has a value).

## Register variant: gender-neutral (default) vs. historical

Orthogonal to the DE/EN language axis, the app has a **register** setting
(`localStorage["yijing-register"]`, default `"neutral"`; toggle in Settings):

- **neutral** (default) — every generic, gender-implying reference to a *person*
  (the everyman / the querent) is de-gendered, across **all** text dimensions
  (judgment, image, meaning, every line text + interpretation, notes): role nouns
  ("der Edle" → "die edle Person", "der große Mann" → "der große Mensch", "the
  superior man" → "the superior person") **and** the generic pronouns that follow
  (DE: pronouns agree with the neutral noun — "die edle Person … sie/ihr";
  generic everyman "er" recast to "man"/plural. EN: singular *they/their*).
  Content-specific gendered figures are preserved verbatim: the marrying maiden,
  woman, the Father/Mother/Son/Daughter trigram roles, king/prince, the dragons.
- **historical** — Wilhelm's 1924 wording verbatim (the base fields).

Coverage is **per language, not symmetric**: German and English gender
differently (German's impersonal "man" is already neutral, English "he" is not),
so a field legitimately carries a neutral override in one language but not the
other. Stored as **overrides only where they differ** from the base: `*_neutral`
(DE) / `*_en_neutral` (EN) on `meaning`/`judgment`/`image`, per line
(`text_neutral`/`interpretation_neutral` + `_en_` variants) and per note. A
missing `*_neutral` means "already neutral — identical to historical" (the app
resolves `field_neutral ?? field`).

Source of truth: **`scripts/sources/neutral_overrides.json`** (committed). Built
in layers: a deterministic regex pass for role nouns (`scripts/neutralize.py`),
then an LLM completion + pronoun polish over all 64 hexagrams, then an
adversarial leak/fidelity audit (no generic gendered person-reference survives in
the neutral register; content unchanged otherwise). Applied with
**`scripts/apply_neutral.py`** (idempotent; run *after* `build_data.py`, which
rebuilds the DE base and drops the neutral fields until re-applied).
`test-kingwen.mjs` verifies every stored `*_neutral` is non-empty and actually
differs from its base (no redundant copies); it does **not** force DE⟺EN parity
(per-language coverage is expected).

## Source license

- **Wilhelm texts** (`meaning`, `judgment`, `image`, `lines[].text`,
  `lines[].interpretation`): from Richard Wilhelm, *I Ging — Das Buch der
  Wandlungen*, first edition 1924. Wilhelm died in 1930 — the translation has been
  in the public domain in Germany since 2001 (70 years p.m.a.).
- **Chinese designations and Pīnyīn**: from Wikipedia / Wiktionary
  or from the original Chinese text — public domain as a
  historical source (>2000 years old).
- **Trigram reference data**: from standard literature (Wilhelm,
  Vogelmann, etc.). Factual.
- **Image associations** (19 of them): self-created, own prompts.
